一、当前炮塔运动架构

┌─────────────────────────────────────────────────────────┐ │ tankGroup (车身) │ │ rotation.y = π/2 − hullYaw ← 差速转向驱动 │ │ │ │ ┌─────────────────────────────────────────────┐ │ │ │ turretPivot (炮塔) │ │ │ │ rotation.y = turretYaw ← 相对车身的局部角度 │ │ │ │ │ │ │ │ ┌─────────────────────────┐ │ │ │ │ │ barrelPivot (炮管) │ │ │ │ │ │ rotation.x = elevation │ │ │ │ │ └─────────────────────────┘ │ │ │ └─────────────────────────────────────────────┘ │ └─────────────────────────────────────────────────────────┘ 世界炮塔朝向 = (π/2 − hullYaw) + turretYaw

三条控制路径同时作用于 turretYaw

路径 代码位置 机制 速度
稳定器 engine.js:1108 turretYaw += hullDyaw — 车体转多少，炮塔反向补偿多少 ⚡ 瞬时（无限速度）
鼠标瞄准 engine.js:1188-1194 世界瞄准点 → invQ局部空间 → angleMoveToward(turretYaw, targetYaw, …) 🐢 限速 30°/s
手柄右摇杆 engine.js:1135 turretYaw += stick * 0.5236 * dt — 摇杆偏转→角速度 🎮 比例速度

二、问题根因：瞬时补偿 vs 限速瞄准 互搏

场景：玩家按 D 右转 + 鼠标右移瞄准

时间线（一帧内）： ┌──────────────────────────────────────────────────────┐ │ │ │ ① 车体右转 Δ° │ │ ↓ │ │ ② 稳定器：turretYaw += +Δ （瞬时，无限速） │ │ │ │ ③ 车体右转 → 世界瞄准点的局部角度反而变小 │ │ （车身迎向目标，局部 targetYaw ↓） │ │ ↓ │ │ ④ angleMoveToward 想减小 turretYaw │ │ 但只能以 30°/s 慢速纠偏 │ │ │ │ ⚠️ ② 往上冲，④ 往下拉 → 互搏 → 炮塔几乎不动 │ │ 车体和鼠标明明同向，炮塔却像卡住一样 │ └──────────────────────────────────────────────────────┘

一句话：瞬时补偿（∞速度）和限速瞄准（30°/s）在同一个变量上打架。
稳定器已经"过度补偿"了，瞄准系统只能慢速纠偏，造成"同向转反而迟钝"的体感。

三、三种解决方案

方案 A：完全解耦 激进

删除 engine.js:1108 的稳定器行，炮塔纯跟鼠标/摇杆，车体转动不再补偿。

改动：删除一行 - player.turretYaw += hullDyaw; // ← 就这一行 效果：turretYaw 完全由鼠标/摇杆单独决定 车体右转 → 世界炮口也跟着右转（无补偿） 玩家必须手动修正鼠标来保持瞄准

✅ 有利

  • 同向转不再打架，炮塔满 30°/s 追光标
  • 操控模型极简：炮塔=光标，无隐藏魔法
  • 真实 WWII 坦克体验（T-34 无稳定器）
  • 代码最简，只删一行

❌ 不利

  • 行进间车体转动，炮口在世界空间会漂
  • W+D 斜行+瞄准时，车身持续把炮塔带偏
  • 对新手不友好：边开车边瞄准需高度协调
  • 手柄双摇杆（左摇杆转+右摇杆瞄）体感类似

方案 B：世界空间瞄准 推荐

将瞄准逻辑从局部空间搬到世界空间，稳定器的效果变为限速 30°/s 的自然结果。 

// 替换 engine.js:1108 和 1188-1194

// 1. 世界空间目标方向（从鼠标射线，当前已有）
const worldTargetYaw = Math.atan2(worldDir.x, worldDir.z);

// 2. 当前炮塔世界朝向
const worldTurretYaw = Math.PI/2 - hullYaw + turretYaw;

// 3. 限速追目标（稳定器效果在此，速度=30°/s，非瞬时）
const newWorldYaw = angleMoveToward(worldTurretYaw, worldTargetYaw, turretAngVel * dt);

// 4. 反算局部 turretYaw（车体转了多少自动吸收，不打架）
turretYaw = normalizeAngle(newWorldYaw - (Math.PI/2 - hullYaw));
关键区别：旧稳定器是瞬时（无限速度），新稳定器受 30°/s 马达限速。 车体急转时炮塔会滞后（真实电机做不到瞬时），但不会和鼠标打架。
类比：旧 = 魔法瞬移，新 = 真实电机追目标。

✅ 有利

  • 同向转不打架（都在世界空间追同一个目标）
  • 稳定器效果保留但真实化（有限马达速度 30°/s）
  • 鼠标和手柄走同一条世界空间路径，逻辑统一
  • 对新老玩家都友好——车转炮不立刻漂，但有真实滞后

❌ 不利

  • 代码改动比方案A大（~15行）
  • 需要处理角度归一化边界
  • 如果后续觉得"太稳"，想切方案A反而多了一步

方案 C：只调顺序 最小

稳定器放到 angleMoveToward 之后执行，改动最小但对同向转改善有限。

// 先让鼠标驱动炮塔追目标
player.turretYaw = angleMoveToward(player.turretYaw, targetYaw, turretAngVel * dt);
// 再叠加稳定器补偿（延迟一帧）
player.turretYaw += hullDyaw;

效果有限：本质问题（瞬时 vs 限速的互搏）没解决，只是改了叠加顺序。同向转改善微乎其微。不推荐。

🏆 推荐：方案 B — 世界空间瞄准

理由：

  1. 根治问题 — 消除瞬时补偿和限速瞄准的互搏，同向转不再迟钝
  2. 稳定器真实化 — 保留稳定器手感但限速 30°/s（像真实炮塔马达），而非极端完全取消
  3. 一致体验 — 车体怎么动，炮塔始终以稳定速率追光标，体感可预测
  4. 可降级 — 如果觉得"还是太稳"，切到方案 A 只需删一行代码
  5. 敌我统一 — 敌方坦克的炮塔逻辑（engine.js:3289-3291）也可以同一方式改造
