# 人形敌人流水线设计（用户既定架构，2026-08-14 用户重申）

## 核心管线

```
骨架（成年中性/成年男/成年女/儿童 等版本）
  │  ① 每个骨架维护【自己的一套基本动画】（restPoses + 6 动作关键帧），
  │     骨架间互不共享（2026-08-14 用户确认）
  ▼
bakeModel() 烘焙变体（学生/教师/未来：军人/警察/矿工 等）
  │  ② 变体继承【所属骨架】的动画配置（MODELS[v].anims = 骨架.anims）
  ▼
变体微调动画（可选）
  │  ③ 仅当该变体有特殊设定（专属武器/动作）才微调，否则零动画工作
```

## 用户意图（原话要点，2026-08-14 二次确认）

- 关卡"流水线式"生成人形敌人：本关校园人物，下关可能军队/警察局/矿井
- **不想为每个具体人形敌人适配动画**，除非它有特殊设定
- 顺序：**针对骨架做基本动画 → 烘焙的变体再微调各自的动画**
- **每个骨架维护一套基本动画**，不是所有骨架共享一套；未来的标准人形敌人
  基本符合现在这三个骨架（成年/女/儿童），直接套用对应骨架动画

## 当前实现与管线的差距（2026-08-14 查证）

1. ✅ 动画系统已骨架级通用：`createHumanoidAnimationSystem(root)` 用 `HC.JOINT_NAMES` 遍历
   + `root.getObjectByName(n+'_pivot')`，任何从骨架派生的变体自动获得动画
2. ⚠️ **REST_POSES 是全局单份**（`humanoid_config.js`），其中 `'pelvis:y': 0.375` 是写死的基线；
   用户已把成年中性/女调成 pelvis=0.5、男/儿童=0.375 → **不同版本基线不一致，
   播放动画时 pelvis 会被拉回 0.375 基线 → 错位**。需把 REST_POSES 按骨架版本化
   （或烘焙时动态注入该版本的 pelvis 基线）
3. ⚠️ 动画关键帧**双份镜像**：`models/enemies.js:createHumanoidAnimationSystem`（游戏侧）
   + `js/humanoid_factory.js`（工厂展台），改动作必须同步两处（已知问题）
4. 游戏侧动画创建在 `enemies.js` createCampusZombie 流程内；未来新关卡人形需复用同一
   createHumanoidAnimationSystem（函数在 enemies.js 内部，新单位构建时调用即可）
